# Replay Expectations — DanceTrack 回放测试片验收基准

本文件是 6 条 DanceTrack 回放测试片的**人工验收基准**。
- **关键事件时间点**:由 Code 从各序列 `gt.txt` 的 id 消失→重现(缺 >10 帧)换算成秒(下方表格),
  是**全帧 gt** 的遮挡时刻。
- ⚠️ **裁剪放大效应**:6 条片都做了 9:16 中心裁剪(1080p 只留中间 ~32% 宽)。锁定主角与旁人会**更频繁**地
  离开竖屏视野,所以**实测 clip 上的 SEARCHING/LOST 次数 ≥ 表中 gt 事件数**——这些时间点是"至少会发生遮挡"的下界参考,不是精确预测。
- **锁定对象**:app 开场 auto-lock 锁**最大框**(通常是画面中央离镜头最近的那个),不一定是 gt 里的 id 0/1。
- **预期行为**一栏留给 Zc 人工填(跑完对照 HUD + `Documents/ReplayLogs/*.log` 的 SUMMARY)。

数据源:`~/Datasets/DanceTrack_subset/val/*/gt/gt.txt` + `seqinfo.ini`(均 20fps 原生;转码保时长,故秒数直接通用)。

### 跑法
Debug 包 → 回放测试界面 → 「🎬 DanceTrack 回放测试」段选片 → 播完自动停末帧,
HUD 第0行显示 `clip · f/total · t`,`Documents/ReplayLogs/{clip}_{时间戳}.log` 末尾有 REPLAY SUMMARY。
对照:SUMMARY 的 `searching→lost` 应仅在 clip_5 >0;`SHADOW-FALLBACK 其中iou>0.5且候选1` 若 >0 说明有"本该被 SOLO-PASS 接住却没接住"的场,贴日志段归因。
